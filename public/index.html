Analytics without tracking people

Every redirect records the browser, operating system, device and the site that sent the visitor. IP addresses are salted and hashed, never stored, and click logs delete themselves after 90 days.

A heartbeat on the destination

Turn on the uptime check and URLPulse visits the target page on a schedule. A passing check draws a beat, a failing one draws a flatline, and two failures in a row mark the link as down.

How a redirect works

A lookup asks Redis first. On a miss it reads MongoDB and fills the cache for next time. Clicks are queued in memory and written in batches, so the visitor never waits for analytics.

Every change ships through a pipeline

Nothing reaches the server by hand. A push to main runs the whole chain, and any failing step stops it.

  1. Push

    A commit or pull request starts GitHub Actions.

  2. Lint and test

    ESLint, then unit, integration and end-to-end tests against real MongoDB and Redis.

  3. Build

    A multi-stage Docker image that runs as a non-root user.

  4. Scan

    Trivy fails the build on any critical vulnerability that has a fix.

  5. Publish

    The image goes to Docker Hub tagged with the commit and latest.

  6. Deploy

    Docker Compose pulls the image and restarts the app behind health checks.

  7. Observe

    Prometheus scrapes metrics, Grafana charts them and alerts fire on trouble.
